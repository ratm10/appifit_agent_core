AppFitNotifierService는 WebSocket을 스스로 살려두는 상태 머신이다. 끊기면 지수 backoff로 재시도하고, 최대 횟수를 소진하면 능동 재시도를 멈추고 네트워크 복원 이벤트를 기다린다. 하트비트가 Ghost 연결을 감지해 강제로 재연결 궤도에 태운다. 상세는 NotifierService L4.
연결 상태 (ConnectionStatus)
initialConnected
앱 시작/로그인 후 최초 연결 성공
_hasEverConnected=false 일 때
reconnected
끊김 후 복구 성공
이후 성공은 전부 이 상태
reconnecting
backoff 대기 포함 재시도 중
_handleDisconnection 진입
disconnected
최대 초과 또는 의도적 종료
복원 이벤트 대기
전이 (Transition)
connect() → initialConnected
apiKey를 encryptAesGcm로 암호화해 헤더에 싣고 WebSocket.connect().timeout(20s). 성공 시 backoff·타이머 리셋 + heartbeat 시작
open → reconnecting
onError/onDone 또는 heartbeat(60s)가 readyState != open 감지 → _handleDisconnection(중복 가드) → cleanup → _scheduleReconnect
reconnecting ↻ reconnecting
지연 min(3 × 2^attempt, 300)초 = 3→6→12→24→48→...→300. 시도 카운트 증가 후 타이머 예약
reconnecting → disconnected
시도 5회 초과 시 능동 재시도 중단 — connectivity_plus 복원 이벤트 대기 모드로
복원 이벤트 → reconnecting
notifyNetworkRestored() — wifi/mobile/ethernet 감지 시 backoff 초기화 후 즉시 재연결(연결/시도 중이면 무시)
disconnect() → disconnected
로그아웃 — 타이머·connectivity·연결 정리 + 캐시 4종 null → 재연결 불가화

heartbeat/onError/onDone 동시 호출에도 끊김 처리 1회
_isDisposed

하트비트 · Ghost 감지
heartbeat 60s
주기마다 readyState 점검 — open이 아니면 즉시 재연결 궤도. 정상 로그는 디버그 빌드만(프로덕션 노이즈 억제)
wsPing 25s
프로토콜 레벨 ping — 서버 pong 미응답 시 onDone 자동 발화(OS 소켓이 감지)
Ghost 임계 5분
마지막 메시지 후 5분 무수신은 의심 신호(readyState는 open인데 데이터 없음)
→ NotifierService L4 상세
이 상태 머신의 핵심: 소켓은 실시간 채널이자 폴링의 트리거다 — 소비자 앱은 connectionStateStream을 구독해 연결 시 60s·끊김 시 15s로 폴링 간격을 조인다(AppFitSyncIntervals). 즉 소켓이 죽어도 폴링이 안전망으로 주문을 계속 건져 올린다.
